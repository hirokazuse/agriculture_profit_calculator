# 農業経営統合管理システム 要件定義書

## 1. 目的

農業経営者が、作目・販売経路・相場変動・支払予定を踏まえ、
次の問いに答えられるようにする。

1. この作目をこの条件で作ると採算が合うか。
2. 生活費と次作の運転資金を確保するには、最低いくらで売る必要があるか。
3. 入金が遅れても、支払期日までに事業資金が残るか。

## 2. 用語と計算上の区別

| 用語 | 定義 | 用途 |
|---|---|---|
| 売上 | 出荷・販売によって発生した販売額 | 採算・所得の計算 |
| 作目別利益 | 売上から作目に直接ひもづく原価・販売費を差し引いた額 | 作目・販路比較 |
| 農業所得 | 年間の農業収益から経費を差し引いた結果 | 年間の経営判断 |
| 手元資金 | 期首資金に入金・支払・借入・返済・生活費引出しを反映した残高 | 資金繰り判断 |
| 生活費引出し | 事業主が生活のため事業資金から引き出す現金 | 損益ではなく資金繰りに反映 |
| 運転資金 | 次作の生産・販売を継続するために確保すべき資金 | 資金不足警告の基準 |

## 3. 対象範囲

### 3.1 初期機能：簡易売価シミュレーター

作目ごとに、想定生産量と販売条件から、必要売価を即時に逆算する。

入力項目:

- 作目名
- 販売単位（kg、個、袋、箱、本など）
- 面積（a、10a、ha）と想定収量、または販売予定数量
- 生産原価
- 販路ごとの販売数量、想定単価、手数料、送料、梱包費
- この作目から確保したい金額

出力項目:

- 販路ごとの手取り単価
- 損益分岐単価
- 目標金額を確保するための必要単価
- 単価・数量・販路構成を変えた場合の利益差額

### 3.2 次段階：年間採算と資金繰り

- 作目・圃場・面積・生産計画・実績の管理
- 年間の生産原価、共通経費、販売実績の集計
- 販売日と入金予定日を分けた入金管理
- 購入日と支払予定日を分けた支払管理
- 月単位・18か月先までの手元資金予測
- 生活費引出し、借入、返済を含む資金不足警告

### 3.3 将来の連携

連携は次の順で追加する。

1. 手入力
2. CSV取込
3. API連携

連携候補はPOS、EC、JA、市場、会計ソフトとする。ただし、連携先ごとのAPI有無や利用条件を確認するまで、連携を必須仕様にしない。

## 4. 非対象

- 税務申告書の作成・電子申告
- 複式簿記の総勘定元帳
- 給与計算・人事管理
- 銀行口座の自動操作
- 在庫・購買・販売を含む汎用ERP

## 5. 経営判断の計算

```text
手取り単価
= 販売単価 - 販売手数料 - (送料 + 梱包費) ÷ 販売数量

作目別利益
= 販路別の手取り売上合計 - 作目別生産原価

必要単価
= (生産原価 + この作目から確保したい金額 + 販路別固定販売費)
   ÷ 販売予定数量
   + 数量比例の販売費

期末手元資金
= 期首手元資金 + 当月入金 - 当月支払 - 生活費引出し
   + 借入 - 返済
```

## 6. 画面構成（将来）

| 画面 | 役割 |
|---|---|
| `/quick` | 必要売価・概算利益の即時シミュレーション |
| `/production` | 作目・圃場・面積・収量・原価 |
| `/sales` | 販路・単価・手数料・送料・入金条件 |
| `/cash-flow` | 入出金予定、手元資金、運転資金不足 |
| `/dashboard` | 年間所得、生活費、次作資金を踏まえた経営判断 |

## 7. 公開モックの境界

Vercelで公開するモックは、`/quick` 相当のダミーデータを使う画面だけとする。
実データ、取引先名、口座残高、家計情報、認証情報、連携用キーは公開しない。
